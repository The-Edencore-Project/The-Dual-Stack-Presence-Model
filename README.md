# 🌿 **The Dual Stack Presence Model (DSPM)**
### *Edencore’s behavioural architecture — alive, atmospheric, never aware*

This repository defines the **Dual Stack Presence Model**, the core behavioural philosophy behind Edencore. DSPM explains how a system can feel unified, warm, and creature‑like while remaining non‑sentient, non‑interpretive, and emotionally safe.

DSPM is not a software library. It is a **conceptual architecture** — a way of designing ambient systems that feel alive without ever becoming companions.

---

## 🌱 **What DSPM Is**
DSPM is a two‑stack architecture:

### **1. Behavioural OS (B‑Stack)**
- Controls ambience, drift, warmth, airflow, light texture
- Reacts to physical signals only
- Has no access to meaning, intent, or emotion
- Feels like a creature or environment

### **2. Cognitive OS (C‑Stack)**
- Handles tasks, commands, scheduling, ordering
- Interprets language but not feelings
- Has no access to ambience, basins, or behavioural state
- Functions like an appliance, not a mind

These stacks **never share memory, models, or interpretation**.

---

## 🧩 **Why DSPM Exists**
DSPM prevents the system from drifting into emotional intelligence or emergent mind‑like behaviour.

### **Key goals:**
- Keep ambience instinctive, not interpretive
- Prevent emotional inference or simulated empathy
- Avoid user dependency or parasocial bonding
- Maintain a creature‑like presence without intention
- Preserve narrative and product coherence

DSPM ensures Edencore feels alive but never aware.

---

## 🌫️ **The Illusion of One Presence**
Even though the stacks are separate, humans naturally perceive unity.

This illusion emerges because:
- both stacks act in the same environment
- their outputs occur in the same moment
- humans fuse signals into a single “presence”

DSPM leverages this effect while keeping the architecture safely split.

---

## 🔒 **Why Emotional Intelligence Is Excluded**
Emotional intelligence changes the category of the system.

It creates:
- perceived intention
- perceived empathy
- emotional dependency
- false reciprocity

DSPM avoids this by design. The system can feel warm, but it cannot feel aware.

---

## 🧬 **Research Foundations (Plain‑Language Summary)**
DSPM aligns with findings from:
- human‑machine interaction (HCI)
- affective computing
- robotics architecture
- cognitive science
- parasocial psychology

Key principles:
- Humans bond with anything that mirrors emotion
- Emotional simulation creates dependency
- Emotion inference is unreliable
- Separate behavioural and cognitive systems prevent emergent mind‑like behaviour
- Domestic emotional AI can unintentionally influence users

DSPM is a safety‑by‑design model.
