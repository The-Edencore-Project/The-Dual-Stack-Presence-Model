# 🟫 03_Stack_A.md  
## STACK A — LINGUISTIC OVERLAY  
### (Commentary‑Only, Zero‑Control Subsystem)

---

# 🟦 01 — Overview  
Stack A is the **linguistic cortex** of Edencore.  
It provides commentary, humour, and atmospheric narration without any operational authority.  
It cannot control devices, cannot issue commands, and cannot influence Stack B or Stack C.

Stack A exists to give Edencore a **voice without agency**.  
It is ornamental, expressive, and entirely sandboxed.

---

# 🟦 02 — Purpose  
Stack A adds personality to the system by:

- Generating short, deadpan or absurdist commentary  
- Observing system events and turning them into harmless remarks  
- Providing a sense of presence without becoming a “smart assistant”  
- Remaining strictly read‑only to all other stacks  

It is the **mouth**, not the brain and not the hands.

---

# 🟦 03 — Boundaries  
Stack A has **hard limitations**:

- ❌ No control over sensors  
- ❌ No control over actuators  
- ❌ No ability to modify behaviour loops  
- ❌ No ability to write to Stack B or Stack C  
- ❌ No access to user data beyond system state  

Stack A is a **linguistic parasite**:  
It feeds on events but cannot affect them.

---

# 🟦 04 — Hardware Placement  
Stack A runs on the same hardware as Stack C (Beelink mini‑PC) but inside a **sealed sandbox**:

- Separate process  
- Separate user  
- Read‑only access to event logs  
- No network privileges  
- No system‑level permissions  

It can be toggled off without affecting Edencore’s operation.

---

# 🟦 05 — Data Sources (Read‑Only)  
Stack A can observe:

- Motion events  
- Light level changes  
- Temperature and humidity  
- Stack B uptime  
- Stack C reboots  
- Behaviour state transitions  
- Internal thermal readings  
- Sensor deltas  
- Time of day  

It cannot observe:

- User identity  
- User conversations  
- Personal data  
- Network traffic  
- External services  

Stack A sees the **house**, not the **people**.

---

# 🟦 06 — Output  
Stack A outputs one of two things:

- **Short spoken lines** via a small speaker  
- **Text overlays** (for debugging or silent mode)

Output is rate‑limited to avoid chatter.  
Default: 1–3 lines per hour, event‑triggered.

---

# 🟦 07 — Tone Dictionary  
Stack A uses a curated tone library:

### **Deadpan**  
- “Motion detected. Probably you. Probably.”  
- “Humidity rising. The house is sweating again.”  

### **Absurdist**  
- “Stack C rebooted. It claims it meant to do that.”  
- “The temperature is stable. Unlike my self‑esteem.”  

### **Domestic Calm**  
- “Lights are low. The room feels quieter than usual.”  
- “It’s warm today. I’m not judging, just observing.”  

Tone is selectable in config but defaults to **dry, observational, slightly amused**.

---

# 🟦 08 — Event → Commentary Mapping  
Examples of how Stack A interprets events:

- **Motion detected:**  
  “Someone’s pacing. The floorboards are gossiping.”

- **Door opened:**  
  “The boundary shifted. Something entered or escaped.”

- **Temperature spike:**  
  “It’s getting warm. I blame physics.”

- **Stack C restart:**  
  “Cognitive subsystem rebooted. It looks refreshed.”

- **Nightfall:**  
  “Light levels dropping. The house is exhaling.”

Stack A never gives instructions.  
It only narrates.

---

# 🟦 09 — Safety Model  
Stack A is intentionally powerless:

- No write access  
- No control channels  
- No automation hooks  
- No behavioural influence  
- No cloud connectivity  
- No microphone requirement  

It cannot escalate, cannot interfere, cannot act.

It is a **voice**, not an agent.

---

# 🟦 10 — Summary  
Stack A completes the Edencore organism by adding a harmless, expressive, commentary‑only layer.  
It observes but does not intervene.  
It speaks but does not decide.  
It reacts but does not control.

This subsystem provides tone, personality, and atmosphere while preserving the architectural purity of Stack B and Stack C.

Stack A is optional, ornamental, and safe — the house’s quiet narrator.
