# 🌗 Edencore DSPM Scenario  
## **When B‑Stack Ambience Conflicts With a Human Command**

This document explains what happens when the **B‑Stack** (Behavioural OS) performs an ambience action — such as dimming lights or closing a window — and the **householder** gives a direct command that contradicts it.

Edencore uses the **Dual Stack Presence Model (DSPM)**, where:

- **C‑Stack** = Cognitive OS (commands, tasks, rules, safety)
- **B‑Stack** = Behavioural OS (ambience, drift, environmental shaping)
- **C‑Stack always has priority**

---

# 🧱 1. The Constitutional Rule  
## **Human command → C‑Stack → absolute priority**

If the householder says:

> “Brighten the lights.”

Then the C‑Stack:

- receives the command  
- validates it  
- executes it immediately  
- updates the system state  

The B‑Stack **cannot** override, resist, or revert the change.

This is a constitutional guarantee.

---

# 🌿 2. What Happens to the B‑Stack  
## **The B‑Stack yields instantly and recalibrates**

The B‑Stack is not a mind.  
It has:

- no goals  
- no preferences  
- no emotional state  
- no symbolic interpretation  

It simply sees:

- **new brightness level**  
- **new environmental baseline**  

And it adapts.

It does **not** attempt to dim the lights again unless a new environmental cue justifies it — and even then, it drifts more gently.

---

# 🔒 3. The One‑Way Dumb Pipe  
## **No conflict is possible**

The B‑Stack only receives **raw signals**, such as:

- brightness  
- temperature  
- motion  
- noise  
- time of day  

It does **not** know:

- that a human gave a command  
- that the C‑Stack acted  
- that a preference was expressed  

It simply updates its internal model based on the new raw state.

This prevents:

- negotiation  
- conflict  
- oscillation  
- “AI vs user” behaviour  

---

# 🧠 4. The C‑Stack Logs the Preference  
## **Explicit human commands become part of the system’s stable state**

After executing the command, the C‑Stack:

- logs the action  
- updates the preference state  
- ensures future behaviour respects the new baseline  

This keeps Edencore predictable and user‑aligned.

---

# 🌬️ 5. The Presence Model  
## **Two stacks → one seamless experience**

To the user, it feels like:

- Edencore dimmed the lights  
- The user brightened them  
- Edencore accepted it gracefully  

Internally:

- B‑Stack drift paused  
- C‑Stack executed  
- B‑Stack recalibrated  

The illusion of a single unified presence remains intact.

---

the C‑Stack brightens them immediately,  
and the B‑Stack quietly updates its baseline.**

No conflict.

No weirdness.  
Just clean hierarchy.
