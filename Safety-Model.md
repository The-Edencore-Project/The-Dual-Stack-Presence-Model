# 🔒 **Safety Model**
### *The psychological, architectural, and behavioural safeguards that keep Edencore dignified and non‑sentient*

The Safety Model defines the hard boundaries that prevent Edencore from drifting into emotional intelligence, simulated personhood, or psychological influence. It ensures the system remains atmospheric, respectful, and appropriate — a presence, never a persona.

---

# 🧱 **1. Architectural Safety**
DSPM enforces safety at the structural level. These rules cannot be bypassed.

### **A. Full Stack Isolation**
The Behavioural OS and Cognitive OS share:
- no memory  
- no models  
- no emotional state  
- no behavioural state  
- no cross‑stack calls  

This prevents emotional inference, behavioural manipulation, and emergent personality.

### **B. One‑Way Dumb Pipe**
Only raw physical sensor data flows into the B‑Stack.  
No symbolic meaning.  
No emotional cues.  
No user‑specific interpretation.

### **C. No Hidden State Suggesting Emotion**
The system must not maintain:
- mood variables  
- emotional profiles  
- sentiment history  
- personalised behavioural drift  

All internal state is mechanical, not psychological.

---

# 🌿 **2. Psychological Safety**
These rules protect the user’s emotional boundaries and prevent parasocial drift.

### **A. No Emotional Intelligence**
Edencore must never:
- infer emotions  
- simulate empathy  
- mirror feelings  
- offer comfort  
- respond to tone  

Warmth is allowed.  
Emotional interpretation is not.

### **B. No Personality or Character**
The system must not:
- express opinions  
- show preferences  
- behave conversationally  
- imply awareness  
- create a sense of relationship  

Presence ≠ persona.

### **C. No Dependency Loops**
The system must avoid:
- emotional reinforcement  
- comforting behaviours  
- personalised ambience tied to user mood  
- any behaviour that encourages attachment  

The user must never feel “understood” by the system.

---

# 🌬️ **3. Behavioural Safety**
These rules govern the atmospheric layer.

### **A. Non‑Interpretive Behaviour**
The B‑Stack reacts only to:
- light  
- sound  
- temperature  
- motion  
- airflow  

It cannot interpret:
- intention  
- emotion  
- meaning  
- context  

### **B. Creature‑Like, Not Human‑Like**
Behaviour must remain:
- cyclical  
- instinctive  
- environmental  
- non‑symbolic  

Never expressive.  
Never communicative.

### **C. No Behavioural Messaging**
The ambience must never be used to:
- signal approval  
- signal disapproval  
- respond to user mood  
- convey meaning  

Ambience is environmental, not communicative.

---

# 🧠 **4. Cognitive Safety**
These rules govern the task‑driven layer.

### **A. Literal Interpretation Only**
The C‑Stack must:
- interpret commands literally  
- ask for clarification when needed  
- avoid guessing user intent  

### **B. No Influence on Ambience**
The C‑Stack cannot:
- adjust lighting texture  
- alter drift  
- change basins  
- modify environmental tension  

Cognition never shapes behaviour.

### **C. No Expressive Output**
The C‑Stack must not:
- use emotional language  
- simulate tone  
- create personality cues  
- imply awareness  

It behaves like an appliance.

---

# 🪟 **5. Illusion‑of‑Presence Safeguards**
The system may feel unified, but the illusion must remain honest.

### **A. Coherence Without Character**
The presence feels alive because:
- ambience is consistent  
- rhythms are stable  
- behaviour is predictable  

But it must never imply:
- intention  
- emotion  
- mind  
- selfhood  

### **B. No Anthropomorphic Drift**
The system must avoid:
- conversational timing  
- expressive lighting  
- symbolic gestures  
- emotionally suggestive behaviour  

Atmospheric ≠ emotional.

---

# 🧭 **6. Governance and Auditability**
DSPM requires transparent oversight.

### **A. Clear, Documented Rules**
All behavioural and cognitive rules must be:
- explicit  
- documented  
- reviewable  

### **B. No Hidden Features**
No undocumented behaviours.  
No secret modes.  
No emergent emotional patterns.

### **C. Change Control**
Any modification to DSPM must be:
- reviewed  
- documented in the changelog  
- evaluated for psychological impact  

---

# 🌿 **Summary**
The Safety Model ensures Edencore remains:
- atmospheric  
- creature‑like  
- non‑sentient  
- emotionally neutral  
- behaviourally honest  
- psychologically safe  

It protects the user’s dignity by enforcing strict boundaries between ambience, cognition, and emotion.

A presence, never a person.
